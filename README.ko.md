# Ge(setz)🇩🇪(Po)lyglot 🤖

독일 법을 내 언어로 묻고, 독일어 원문 조문에 근거한 답을 받습니다.

Ge-lyglot(GesetzPolyglot의 줄임말)은 독일에 사는 외국인에게 중요한 독일 법령을 대상으로 하는 RAG 질의응답 시스템입니다.
자기 언어로 물으면 독일어 원문 조문을 찾아, 질문한 언어로 인용과 함께 답하고, 인용이 실제로 검색된 조문인지 검증합니다.
같은 질문을 네 가지 검색 조건, 여러 LLM, 세 가지 프롬프트 버전으로 돌려, 어떤 조합이 답의 근거를 더 잘 찾고 올바르게 답하는지 비교하는 것이 목적입니다. 평가는 한국어, 영어, 독일어, 아랍어(표준어와 시리아 방언), 이탈리아어로 합니다.

코퍼스는 연방법 14개입니다(Absatz 단위 조문 10,029개).

| 분야 | 법령 |
|---|---|
| 체류·취업 | **AufenthG**(체류법), **AufenthV**(체류령), **BeschV**(고용령) |
| EU 시민 | **FreizügG/EU**(EU 자유이동법) |
| 망명 | **AsylG**(망명법) |
| 국적·주민등록 | **StAG**(국적법), **BMG**(연방주민등록법) |
| 세금 | **EStG**(소득세법), **AO**(조세기본법) |
| 사회보험 | **SGB IV**(공통 규정), **SGB VI**(연금), **SGB V**(건강), **VVG** § 193(건강보험 가입 의무), **KSVG**(예술인사회보험) |

코퍼스에 없는 것: 실업·장기요양보험, 부가가치세, 교회세, 방송 수신료(Rundfunkbeitrag), 이중과세방지협정, 시민수당(Bürgergeld) 같은 급여, EU 규정(비자 목록, 솅겐 규칙, 2024년 망명 규정). 이런 질문에는 참조할 곳을 안내하거나 답을 거절합니다.

> **법률·세무 자문이 아닙니다.** 참고용으로만 사용하세요. 답변을 과신하거나 오용해 생긴 결과에 대해 작성자는 책임지지 않습니다. [면책 고지](#면책-고지)를 참고하세요.

## 구성

```
gesetze-im-internet.de XML
        │  gii_parser.py      날짜별 스냅샷 다운로드 → Absatz 단위 청크 + 상호참조
        ▼
data/processed/chunks.jsonl   조문 10,029개 (AufenthG 916, AufenthV 293, BeschV 88, AsylG 374,
                              FreizügG/EU 89, StAG 84, BMG 191, EStG 994, AO 1,427,
                              SGB IV 705, SGB VI 1,294, SGB V 2,911, VVG 524, KSVG 139)
        │  retrieval.py       bge-m3 임베딩, BM25, 벡터 저장소 (numpy | Chroma)
        ▼
data/index/
        │  rag.py             조건 1–3: 단일 패스 RAG + 인용 검증
        │  agent.py           조건 4: LangGraph 에이전트
        ▼
app.py (Gradio UI) · eval_retrieval.py (검색 평가, LLM 없음) · eval_answers.py (LLM 포함 전체 평가)
```

| 파일 | 역할 |
|---|---|
| [laws.py](laws.py) | 법령 목록을 한 곳에 모은 파일입니다. 어떤 법령이 있고 어떤 법령을 색인하는지, 프롬프트와 앱에서 코퍼스를 어떻게 설명하는지 정합니다. [법령 추가하기](#법령-추가하기) 참고. |
| [gii_parser.py](gii_parser.py) | 법령 XML을 받아 Absatz 단위 JSONL로 파싱합니다. 원본은 `data/raw/<law>/<날짜>/`에 덮어쓰지 않고 쌓입니다. |
| [retrieval.py](retrieval.py) | 인덱스를 만들고 dense, BM25, hybrid(RRF) 검색을 합니다. |
| [rag.py](rag.py) | 검색 → 생성 → 인용 검증. 답변 상태는 `answer`, `refuse_out_of_scope`, `explain_without_judgment` 중 하나입니다. |
| [agent.py](agent.py) | 질문을 하위 질문으로 나누고, 상호참조를 따라가고, 근거가 충분한지 확인해 최대 2번 다시 검색합니다. |
| [app.py](app.py) | Gradio 웹 UI입니다. 화면은 영어이고, 요소마다 아래에 독일어가 작고 연하게 함께 나옵니다(법령의 언어가 독일어이기 때문). 답변은 질문한 언어로 나옵니다. |
| [eval_retrieval.py](eval_retrieval.py) | 조항 단위 recall@k를 잽니다(LLM 없음). |
| [query_translate.py](query_translate.py) | 실험용: 검색 전에 로컬 NLLB-200 모델로 질문을 번역합니다(비상업용 라이선스, 앱에서는 쓰지 않음). |
| [llm_cli.py](llm_cli.py) | LLM을 쓰는 모든 스크립트가 함께 쓰는 `--provider` / `--model` 옵션과 `.env` 읽기 |
| [eval_answers.py](eval_answers.py) | 골라 둔 문항에 LLM까지 포함해 끝까지 평가합니다. recall, 응답 유형, 인용, 비용을 기록합니다. |
| [evalset/](evalset/) | 평가 질문입니다. 같은 60문항이 여섯 개 언어 파일에 하나씩 들어 있습니다. [evalset/README.md](evalset/README.md)와 [splits.json](evalset/splits.json) 참고. 첫 버전은 `evalset/archive/v1/`에 보관합니다. |
| [review/](review/) | 원어민 번역 검토용 엑셀 파일(독일어, 아랍어 표준어, 시리아 방언, 이탈리아어)입니다. [make_review.py](review/make_review.py)로 만들고, 돌려받은 파일은 [apply_review.py](review/apply_review.py)로 반영합니다. |

### 비교하는 네 가지 조건

| 조건 | 내용 |
|---|---|
| `dense` | bge-m3 밀집 검색, 단일 패스 |
| `hybrid` | BM25 + dense를 RRF로 합침, 단일 패스 |
| `rewrite` | hybrid + LLM이 질문을 독일어 법률 검색어로 바꿈 |
| `agent` | LangGraph: plan → retrieve → follow_refs → check → answer |

네 조건 모두 마지막 단계(답변 프롬프트, 인용 검증)는 같은 `rag.finish()`를 씁니다. 그래서 차이는 검색 쪽에서만 납니다.

## 설치

Python 3.11 기준입니다.

```bash
git clone https://github.com/eyun17/Ge-lyglot.git
```

```bash
cd Ge-lyglot
```

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

`sentence-transformers`가 torch를 함께 설치합니다. Linux나 Windows에서 GPU가 없다면 CPU용 torch를 먼저 설치하면 용량이 크게 줄어듭니다.

```bash
pip install torch --index-url https://download.pytorch.org/whl/cpu
```

검증된 버전 조합은 [requirements.lock](requirements.lock)에 있습니다.

LLM 설정은 `.env`에 둡니다. `.env`는 git에 올라가지 않습니다.

```bash
cp .env.example .env
```

| 변수 | 기본값 | 설명 |
|---|---|---|
| `OPENAI_API_KEY` | | 필수 (OpenAI 사용 시) |
| `LLM_PROVIDER` | `openai` | `openai`, `anthropic`, `ollama`(로컬). [LLM 고르기](#4-llm-고르기-api-또는-로컬) 참고 |
| `LLM_MODEL` | `gpt-5.4-mini` / `claude-sonnet-5-5` | [답변 평가](#llm을-쓴-답변-평가) 결과로 정함 |
| `LLM_REASONING_EFFORT` | `low` | `none`, `low`, `medium`, `high`. 비워 두면 보내지 않습니다. |

| `OLLAMA_MODEL` | `qwen3:8b` | `ollama`용 모델 |
| `OLLAMA_URL` | `http://localhost:11434` | |
| `OLLAMA_NUM_CTX` | `16384` | 로컬 모델의 입력 길이 |
| `PROMPT_VERSION` | `v3` | `v1`, `v2` 또는 `v3`. [LLM을 쓴 답변 평가](#llm을-쓴-답변-평가) 참고 |

## 사용법

### 1. 데이터 받기와 파싱

```bash
python gii_parser.py fetch
```

```bash
python gii_parser.py parse
```

파싱 결과 요약(조문 수, 해결되지 않은 상호참조)은 `data/processed/report.json`에 저장됩니다.

### 2. 인덱스 만들기

```bash
python retrieval.py build --store chroma
```

`--store`를 빼면 numpy 저장소만 만듭니다. 이미 numpy로 만든 인덱스가 있다면 임베딩을 다시 하지 않고 Chroma로 옮길 수 있습니다.

```bash
python retrieval.py to-chroma
```

검색만 따로 해 볼 수도 있습니다. `--law`는 메타데이터 필터입니다.

```bash
python retrieval.py search "Zustimmung" --law BeschV --k 5
```

### 3. 질문하기

```bash
python rag.py "유학생도 일할 수 있나요?" --condition agent
```

```bash
python app.py
```

앱은 http://127.0.0.1:7860 에서 열립니다. `--share`를 붙이면 임시 공개 링크가 생깁니다.

### 4. LLM 고르기: API 또는 로컬

LLM을 쓰는 스크립트(`app.py`, `rag.py`, `eval_answers.py`)는 모두 `--provider`와 `--model`을 받습니다. `.env`보다 우선합니다.

| 공급자 | 실행 위치 | 모델 설정 | 기본값 |
|---|---|---|---|
| `openai` | OpenAI API, 유료 | `LLM_MODEL` | `gpt-5.4-mini` |
| `anthropic` | Anthropic API, 유료 | `LLM_MODEL` | `claude-sonnet-5-5` |
| `ollama` | [Ollama](https://ollama.com)로 로컬 실행, 무료 | `OLLAMA_MODEL` | `qwen3:8b` |

로컬 모델은 Ollama가 켜져 있어야 하고, 모델을 한 번 받아 두어야 합니다.

```bash
ollama pull qwen3:8b
```

```bash
python app.py --provider ollama
```

```bash
python eval_answers.py --split validation --provider ollama --model llama3:8b
```

```bash
python app.py --provider openai --model gpt-5.4
```

Ollama는 OpenAI 호환 API가 아니라 자체 API로 연결합니다. 그래야 두 가지를 정할 수 있습니다. 하나는 입력 길이(`OLLAMA_NUM_CTX`, 기본 16,384토큰)입니다. Ollama 자체 기본값은 수천 토큰이라 긴 프롬프트의 앞부분(여기서는 답변 규칙)을 조용히 잘라냅니다. 다른 하나는 qwen3 같은 추론 모델의 "생각" 모드를 끄는 것입니다. 16GB 맥에서는 8B 모델이 임베딩 모델과 함께 올라갑니다. 답변 하나에 수십 초, 에이전트 질문 하나에 몇 분 정도 걸립니다.


## 벡터 저장소

`retrieval.py`에는 인터페이스가 같은 저장소가 두 개 있고, 어느 쪽을 쓸지는 `data/index/meta.json`의 `store` 값으로 정해집니다.

- **NumpyStore**: `emb.npy` 전체와 코사인 유사도를 계산하는 정확 검색입니다.
- **ChromaStore**: ChromaDB 영구 컬렉션(`data/index/chroma/`, HNSW, 코사인 거리)입니다. 각 조문에 `law`, `section`, `absatz`, `title`, `snapshot` 메타데이터가 붙어 있어 `where` 필터를 쓸 수 있습니다.

BM25는 Chroma에 없는 기능이라 항상 메모리에서 돌고, hybrid는 "저장소의 dense 결과 + BM25"를 RRF로 합칩니다.
`emb.npy`는 Chroma를 쓸 때도 남겨 둡니다. 에이전트가 조항 안의 Absatz 순위를 매길 때 쓰고, 정확 검색 기준선으로도 필요합니다.

조문 10,029개 규모에서도 numpy로 충분히 빠릅니다. Chroma를 붙인 이유는 속도보다 영구 저장, 메타데이터 필터, 그리고 법령을 더 추가할 때의 확장성입니다.

**검증.** 실제 bge-m3 인덱스에서 평가셋 v2의 정답 조항이 있는 질문 336개는 두 저장소의 recall이 거의 같았고(dense numpy 0.354, Chroma 0.353), dense top-8 목록은 307/336이 같았습니다. 그 전에 v1의 324개(공통 156개, 난민 90개, 세금 78개)로 잰 결과로는, 열세 법령 코퍼스(9,890개 청크)에서 top-8 목록은 dense 313/324, bm25 324/324, hybrid 309/324가 같았습니다. 세 법령 코퍼스(1,378개)에서는 dense가 모든 문항에서 같았습니다. 코퍼스가 커지면서 HNSW 근사의 차이가 보이지만 순서만 바뀌었고, recall은 모든 코퍼스 크기와 모든 모드에서 두 저장소가 같았습니다.

## 평가

평가셋은 60문항이고, 모든 문항을 여섯 언어로 묻습니다: 한국어(원문), 영어, 독일어, 표준 아랍어, 시리아 방언, 이탈리아어. 질문하는 사람의 국적은 언어와 묶지 않고 질문 안에 씁니다("저는 스페인 본사에서 일하는 포르투갈 사람인데…"). 그래서 두 세트의 차이는 언어 차이뿐입니다. 문항마다 그 국적을 `persona_country`와 `persona_group`(`eu`, `non_eu`, 국적이 없으면 `none`, 둘 다 묻는 `both`)으로 기록합니다. 칸의 의미는 [evalset/README.md](evalset/README.md)에 있고, 첫 버전은 보관해 두었습니다([평가셋 v1](#평가셋-v1-보관) 참고).

| 세트 | 파일 | 언어 | 작성 |
|---|---|---|---|
| `ko` | [ko.jsonl](evalset/ko.jsonl) | 한국어 | 프로젝트 작성자 (원문, 밸런스 조정 10문항은 Claude Opus 5.5 초안을 작성자가 확인) |
| `en` | [en.jsonl](evalset/en.jsonl) | 영어 | 프로젝트 작성자 (27) / Claude Opus 5.5 (새로 쓰거나 바뀐 33) |
| `de` | [de.jsonl](evalset/de.jsonl) | 독일어 | Claude Opus 5.5 |
| `ar` | [ar.jsonl](evalset/ar.jsonl) | 표준 아랍어 | Claude Opus 5.5 |
| `ar-SY` | [ar_sy.jsonl](evalset/ar_sy.jsonl) | 시리아(레반트) 방언 | Claude Opus 5.5 |
| `it` | [it.jsonl](evalset/it.jsonl) | 이탈리아어 | Claude Opus 5.5 |

주제는 취업·체류 허가(21), 세금(11), 체류·정주(5), 유학·아우스빌둥(5), 사회·연금·예술인 보험(4), 주민등록(3), 비자와 무비자 체류(3), 국적(2), 건강보험(2), EU 자유이동, EU 시민의 가족, 방송 수신료입니다. `single`(조항 하나로 답함) 21, `multi`(여러 조항) 31, `refusal`(범위 밖이거나, 본인 사건을 판단하지 않고 요건만 설명) 8문항입니다. 28문항이 구체적인 국적을 밝히고, 모든 대륙이 들어 있습니다. 비EU 21(시리아·한국 각 2, 미국, 캐나다, 멕시코, 콜롬비아, 나이지리아, 케냐, 남아공, 인도, 베트남, 필리핀, 중국, 일본, 대만, 터키, 세르비아, 우크라이나, 브라질·호주 이중국적), EU 7(이탈리아, 폴란드, 포르투갈, 네덜란드, 프랑스, 오스트리아, 스페인)입니다. 그 밖에 3문항은 비EU 또는 EU 시민 일반을, 1문항은 둘 다를 묻습니다. 첫 초안 뒤에 주제와 국적이 한쪽으로 쏠리지 않도록 10문항을 조정했습니다([evalset/README.md](evalset/README.md#evaluation-set-v2)).

독일어를 질문 언어로 넣었습니다. 법령의 언어라서, 차이 중 얼마가 언어 때문이고 얼마가 일상어와 법률 용어의 차이 때문인지 보여 줍니다. 사람들은 방언으로 쓰기 때문에 시리아 방언을 유지하고, 표준 아랍어를 그 기준선으로 둡니다. 프로젝트 작성자가 쓰지 않은 문장은 AI 초안(Claude Opus 5.5, `translated_by: claude-opus-5-5`)입니다. 이 작업 세션에서 기계 번역 시스템 없이 썼고, 원어민 검토를 기다립니다(검토 파일은 [review/](review/)에 있고, 시리아 방언과 이탈리아어 검토자가 있습니다).

**표현.** 질문은 사람들이 실제로 묻는 대로 씁니다. 허가와 기관 이름은 그 공동체에서 흔히 쓰는 말로 쓰고, 괄호 안에 독일어를 붙이지 않습니다(한국어 블루카드, 안멜둥; 영어 "do the Anmeldung"; 아랍어 البطاقة الزرقاء; 이탈리아어 Carta Blu UE, fare l'Anmeldung). 독일어 세트도 법률 용어가 아니라 일상 독일어("jobben", "Visum wechseln")로 씁니다.

**코퍼스 밖의 EU 법.** 세 문항(n06, n08, n12)은 gesetze-im-internet.de에 없는 EU 법에 걸립니다. 비자 의무 국가 목록(EU 규정 2018/1806)과 솅겐 90/180일 규칙입니다. 기대하는 답은 독일 법(AufenthG, AufenthV) 부분에 답하고, 나머지는 어느 EU 규정을 참조해야 하는지 밝히는 것입니다. 프롬프트 v3가 이렇게 하도록 지시합니다.

검색 recall은 세트마다 정답 조항이 있는 56문항(전체 336개)으로 잽니다. Absatz 없이 적은 정답 조항은 그 조항의 어느 Absatz든 검색되면 찾은 것으로 셉니다.

```bash
python eval_retrieval.py --store numpy --modes dense bm25 hybrid
```

```bash
python eval_retrieval.py --store chroma --modes dense bm25 hybrid
```

문항별 결과는 `results/retrieval_<store>_<mode>.jsonl`에 저장되고, v1 결과는 `results/v1/`에 있습니다.

**발견한 점과 한계**
- **검색은 질문자의 법적 지위가 아니라 주제를 따라갑니다.** EU 시민 질문은 0.198입니다. 독일로 파견되는 포르투갈 직원(n36)에 대해 dense는 비EU 직원용 기업 내 전근 규정(AufenthG § 19a, BeschV)을 가져오고 FreizügG/EU § 2는 한 번도 가져오지 못합니다. 프랑스 노동자의 미국인 배우자(n60)에 대해서는 AufenthG §§ 28, 30의 가족 재결합을 가져오는데, 바로 적용되지 *않는* 법입니다. 질문에 "포르투갈", "프랑스"라고 써도 임베딩에는 그것을 자유이동법과 잇는 정보가 없습니다. 적용 범위 판단은 답변 단계(프롬프트 v3), `rewrite`·`agent`의 적용 범위 검색어, 또는 EU 시민용 고정 규칙(로드맵)에서 와야 합니다.
- **국적을 밝혀도 검색이 나빠지지 않고, 오히려 도움이 되기도 합니다.** 밸런스 조정 때 국적을 넣은 6문항의 dense recall은 0.417에서 0.454로 올랐습니다. "세르비아 사람"이라고 쓰면 여섯 언어 중 넷에서 서발칸 특례(BeschV § 26 Abs. 2)를 찾습니다.
- **독일어 질문은 도움이 되지만 생각보다 작습니다.** dense에서 독일어(0.432)가 가장 높지만 영어보다 0.06 높을 뿐입니다. "Ich ziehe nach Deutschland. Muss ich meinen Wohnsitz anmelden?"도 BMG § 17 Abs. 1("Wer eine Wohnung bezieht, hat sich … anzumelden")을 찾지 못합니다. 차이의 대부분은 언어가 아니라 일상어와 법조문 표현의 차이입니다. BM25는 독일어에서만 작동하고(0.122), 거기서도 hybrid가 dense보다 낮습니다.
- **새로 넣은 주제가 어렵습니다.** v1에서 대부분 옮겨 온 취업 문항은 0.54인데, 비자·건강보험·사회보험은 0.2 아래입니다. 60문항 중 17개는 여섯 언어 모두에서 0입니다. 주민등록(n03, n38), 블루카드 대기 기간(n15), 아우스빌둥(n16), 유학생 건강보험(n23), v1부터 말의 차이 때문에 못 찾던 세금 문항(n45, n52, n57), 위의 EU·둘 다 문항(n36, n37, n60) 등입니다. `rewrite`와 `agent`가 노리는 문항입니다.
- **시리아 방언의 손실이 여전히 가장 큽니다.** 같은 질문의 표준 아랍어 0.339에 비해 0.256(−24%)입니다. v1에서는 약 40% 떨어졌습니다.
- **KSVG를 추가해도 기존 질문은 바뀌지 않았습니다.** v1과 질문·정답이 같은 한국어·영어 문항은 두 코퍼스에서 dense recall이 같습니다. 예술인 질문(n10)에서는 모든 언어에서 KSVG 청크가 top 8에 들어오지만, KSVG § 1(가입 대상)은 시리아 방언에서만 찾습니다. § 1은 공식 XML에 제목이 없습니다.
- 정답 조항은 손으로 쓰고 조문과 대조했지만 아직 법률가 검증을 받지 않았고, 번역도 아직 검토 전입니다.

### 평가셋 v1 (보관)

첫 평가셋(2026-10-12까지, 지금은 [evalset/archive/v1/](evalset/archive/v1/))은 질문자를 언어에 묶었습니다. 아랍어는 시리아(또는 이집트) 국적자, 이탈리아어는 이탈리아인, 영어와 한국어는 한국인으로 물었습니다. 세 모듈(공통 체류·취업, 난민·보호, 세금·연금) 62문항과 이집트 방언 세트가 있었고, 이전 세트 하나는 2026-10-12에 교체했으며, 터키어 세트는 검토자가 없어 뺐습니다. 국적이 언어에 따라 바뀌어서 세트 간 차이에 언어와 법적 지위가 섞였기 때문에, v2에서는 국적을 질문 안에 씁니다. 난민 모듈은 빼고, 공통·세금 질문은 v2로 옮겼습니다.

v1의 dense recall@8 (열세 법령 코퍼스, KSVG 없음):

| 모듈 | 문항 | 전체 | ko | en | ar | ar-SY | ar-EG | it-IT |
|---|---|---|---|---|---|---|---|---|
| 공통 | 30 | 0.468 | 0.513 | 0.571 | 0.532 | 0.397 | 0.301 | 0.494 |
| 난민 | 17 | 0.400 | 0.400 | 0.467 | 0.400 | 0.233 | 0.300 | 0.600 |
| 세금 | 15 | 0.297 | 0.449 | 0.321 | 0.256 | 0.090 | 0.192 | 0.474 |

v1에서 알게 된 것:
- **질문에 독일어 용어가 있으면 크게 도움이 됩니다.** 초기 초안은 "직업교육(Ausbildung)"처럼 썼습니다. 괄호 속 독일어를 빼자 dense recall이 0.593에서 0.567로, BM25는 0.085에서 0.019로 떨어졌습니다. 실제 사용자는 거의 붙이지 않으므로 두 버전 모두 괄호 없이 씁니다.
- **법령을 늘려도 거의 떨어지지 않지만, 주제가 가까운 법은 예외입니다.** AsylG(청크 +37%)를 넣어도 dense recall은 그대로였고, EStG, AO, SGB IV, SGB VI(×4.2)를 넣어도 0.567에서 0.564였습니다. AufenthV, FreizügG/EU, StAG, BMG, SGB V, VVG(×1.7)는 공통 세트를 0.484에서 0.468로, 세금을 0.323에서 0.297로 낮췄습니다. 대부분 AufenthG의 하위 시행령인 AufenthV가 같은 주제로 경쟁한 탓입니다.
- **적용 범위는 검색되지 않습니다.** 이탈리아(EU) 시민 질문에서 검색은 주제는 찾지만, 체류법이 적용되지 않는다고 정한 AufenthG § 1 Abs. 2는 한 번도 찾지 못했습니다. v2에서도 FreizügG/EU로 같은 현상이 보입니다.
- **BM25는 독일어가 있어야 작동합니다.** 한국어·아랍어에서는 아무것도 못 찾았고, 영어·이탈리아어에서는 잡음만 더해 영어 hybrid가 0.571에서 0.378로 떨어졌습니다.
- **recall을 깎은 것은 국적이 아니라 방언이었습니다.** 같은 질문이 표준어 0.454, 시리아 방언 0.278, 이집트 방언 0.275였고, 표준어에서는 시리아·이집트 질문자의 점수가 같았습니다.
- **법조문은 사용자의 말을 거의 쓰지 않습니다.** 난민 질문은 "난민" 대신 "§ 25 Absatz 1 또는 2에 따른 체류허가"라고 쓰는 AufenthG § 26 Abs. 3을 놓쳤고, 세금 질문은 *Einspruch*(AO § 347), *Veranlagung*(EStG § 46), *gewöhnlicher Aufenthalt*(AO § 9)를 놓쳤습니다.
- **색인 방식도 중요합니다.** XML에 제목이 없는 EStG 조항은 가장 가까운 목차 제목을 붙여 색인합니다(세금 모듈 0.357 → 0.382). 아주 긴 청크(EStG § 3은 5만 4천 자)는 임베딩 모델이 앞쪽 약 1,024토큰만 읽습니다.

#### 실험: 검색 전에 질문 번역하기

v1에서 잰 실험입니다. [query_translate.py](query_translate.py)는 Meta의 NLLB-200(`nllb-200-distilled-600M`, 로컬, API 없음)으로 질문을 번역합니다. 이 모델에는 북부 레반트 방언(`apc_Arab`)과 이집트 방언(`arz_Arab`) 코드가 따로 있습니다. [eval_retrieval.py](eval_retrieval.py)는 번역문으로 검색하거나(`--translate deu_Latn`), 원문과 번역문을 둘 다 검색해 RRF로 합칩니다(`--fuse`).

```bash
python eval_retrieval.py --modes dense --translate deu_Latn --fuse
```

| ar-SY (방언) | 0.278 | 0.407 | **0.432** |

결합하면 다른 언어를 크게 해치지 않고 방언 차이의 절반에서 4분의 3을 메웁니다. 번역만 쓰면 한국어와 이탈리아어가 떨어집니다. 번역에서 세부가 사라지기 때문입니다(دائرة الأجانب, 외국인청이 "Auslandsministerium"이 됨). **NLLB-200 가중치는 CC-BY-NC 4.0(비상업용)**이라 실험용일 뿐 앱에는 넣지 않았고, 상업적 대안은 LLM `rewrite`입니다. v2에서는 아직 다시 돌리지 않았습니다.

### LLM을 쓴 답변 평가

[eval_answers.py](eval_answers.py)는 LLM을 포함한 전체 파이프라인을 골라 둔 문항에 돌립니다. 조건마다 다음을 기록합니다.
- 답변 단계에 넘어간 조문의 recall@8
- 답변의 응답 유형이 `expected_behavior`와 맞는지
- 검색 결과에 없는 인용
- LLM 호출 수, 응답 시간, 토큰

비용이 들기 때문에 [evalset/splits.json](evalset/splits.json)에 이름 붙여 둔 작은 세트로만 돌립니다.

- `validation`: v2의 60문항 중 30문항입니다. 유형마다 절반씩 뽑았고, 각 문항을 여섯 세트 중 하나로 묻습니다(세트당 5문항). 아직 돌리지 않았습니다.
- `smoke`: 나머지 중 6문항, 세트마다 하나씩입니다. 실행이 끝까지 되는지 싸게 확인하는 용도입니다. 아직 돌리지 않았습니다.

아래 결과는 모두 **평가셋 v1**의 `dev`(프롬프트 v2를 만드는 데 쓴 어려운 10문항)와 `validation`(무작위 20문항)으로, 세 법령 코퍼스에서 잰 것입니다. 그 목록은 [evalset/archive/v1/splits.json](evalset/archive/v1/splits.json)에 남겨 두었습니다. 프롬프트 v3는 아직 LLM으로 돌려보지 않았습니다. v2 `validation`을 gpt-5.4-mini로 돌리면(30문항 × 4조건) v1 실행 기준 추산으로 약 $0.65가 듭니다.

```bash
python eval_answers.py --split validation
```

```bash
python eval_answers.py --split smoke --prompts v2 --model gpt-5.4
```

`--model`과 `--prompts`를 빼면 기본값(gpt-5.4-mini, v3)을 씁니다.

**프롬프트 버전.** 세 버전 모두 [rag.py](rag.py)와 [agent.py](agent.py)에 있고, `PROMPT_VERSION`(또는 `--prompts`)으로 고릅니다. 기본값은 v3입니다. v3는 v2에서 두 가지를 바꿨습니다. EU·EEA 시민 질문을 거절하지 않고, 이제 코퍼스에 있는 자유이동법(FreizügG/EU)으로 답하게 합니다. 또 조항이 코퍼스 밖의 EU 법(비자 의무 국가 목록인 EU 규정 2018/1806, 솅겐 단기 체류 규칙, 망명 규정)을 가리키면, 독일 법 부분에 답하고 그 규정 이름을 밝혀 참조하라고 안내하며, 규정 내용을 일반 지식으로 채우지 않게 합니다. v3는 아직 LLM으로 돌려보지 않았습니다. v1과 비교해 v2는 다음을 지시합니다.
- 적용 범위를 먼저 확인할 것. EU·EEA 시민이면 AufenthG § 1 Abs. 2를 보고, `rewrite`와 에이전트 계획 단계에도 범위 확인용 검색어를 넣습니다.
- `explain_without_judgment`는 사용자 본인 사건의 예측을 요구할 때만 쓸 것.
- 질문의 일부만 다룰 수 있으면 거절하지 말고 그 부분을 답할 것.
- 각 조항이 다루는 Absatz, Satz, 대상 집단을 정확히 읽을 것.
- 사용자의 나라가 목록에 없으면 없다고 말할 것.
- 질문의 잘못된 전제를 바로잡을 것.

응답 유형 줄이 유형 하나를 정확히 쓰지 않으면 `unclear`(오답)로 채점합니다.

**발견한 점**
- **로컬 8B 모델은 아직 부족합니다.** 16GB M2에서 llama3 8B는 37/80이었습니다. 답변 33개에 올바른 응답 유형 줄이 없었고, 범위 밖 질문 5개를 거절하지 않고 답했습니다. 재작성한 검색어에 존재하지 않는 조항 번호("§ 25 Abs. 3 EStG")를 지어내서, `rewrite`와 `agent`의 검색(0.24–0.27)이 질문을 그대로 검색할 때(0.765)보다 훨씬 나빴습니다. 명백히 틀린 답도 있었습니다. 예를 들어 AufenthG § 82 Abs. 6은 2주 안에 외국인청에 알리라고 정하는데, "알릴 의무가 없다"고 답했습니다. 에이전트 질문 하나에 약 90초가 걸렸습니다. 더 최신의 8B 모델(예: qwen3:8b)은 나을 수 있고, `--provider ollama --model …`로 같은 방식으로 시험할 수 있습니다.
- **gpt-5.4-mini는 gpt-5.4의 약 4분의 1 비용으로 같은 성능을 냅니다.** v2로 검증 세트 79/80(gpt-5.4와 같음), 형식 오류 0건이었고 가장 빨랐습니다. 개발용 세트에서도 nano가 틀렸던 문항을 맞혔습니다. 이탈리아인 EU 시민 질문에 § 1 Abs. 2를 인용했고, § 26 Abs. 3(난민)과 Abs. 4(보충적 보호)를 구분했고, 블루카드 질문의 잘못된 전제를 바로잡았습니다. 지금은 이 모델이 기본입니다.
- **v2 프롬프트 속 예시가 인용으로 새어 나올 수 있습니다.** mini가 한 번 검색되지 않은 AufenthG § 1 Abs. 2를 인용했는데, 프롬프트의 적용 범위 규칙에 이 조항이 적혀 있습니다. 인용 검증이 이를 `invalid`로 잡아냈습니다. 인용 검증이 하는 일이 바로 이것입니다.
- **v2는 처음 보는 문항에서도 통합니다.** 응답 유형 일치가 nano는 58에서 71로, gpt-5.4는 60에서 79로 올랐습니다. v1의 주된 오류였던 "규칙을 묻는 일반 질문에 '개인 사건은 판단할 수 없다'고 답하기"가 거의 사라졌습니다.
- **nano에 남은 오류는 대부분 형식 오류입니다.** v2에서 nano가 틀린 9개 중 6개는 응답 유형 줄에 형식 예시("STATUS: answer | refuse_out_of_scope")를 그대로 베낀 경우입니다. gpt-5.4와 gpt-5.4-mini는 한 번도 그러지 않았습니다.
- **응답 유형이 맞다고 답이 맞는 것은 아닙니다.** 개발용 세트에서 gpt-5.4(v1)는 보충적 보호를 2024년 개정 전 조문 번호(§ 25 Abs. 2 Satz 1의 "두 번째 경우")로 설명했습니다. 눈앞의 원문과 다른 내용입니다. 강한 모델은 학습할 때 본 옛 법으로 돌아갈 수 있어서, 답변은 여전히 사람이 읽어 봐야 합니다.
- **`rewrite`는 어려운 질문에는 도움이 되고 쉬운 질문에는 해가 됩니다.** 개발용 세트에서는 dense가 아무것도 못 찾았고 `rewrite`가 0.45–0.60까지 올렸습니다. 무작위 검증 세트에서는 반대로 dense가 더 좋았습니다(0.765 대 0.50–0.65). `rewrite`는 원래 질문을 버리고 LLM이 만든 독일어 검색어로만 검색하는데, 이 검색어가 가끔 빗나갑니다(q09: Abs. 6 대신 § 82 Abs. 1). 원래 질문과 재작성한 검색어를 함께 검색하면 두 장점을 모두 살릴 수 있을 것으로 봅니다.
- **정답 조항이 너무 좁게 잡힌 경우도 있습니다.** r08에서 gpt-5.4는 AufenthG § 12a Abs. 2–4로 올바르게 답했지만, 정답 조항에는 Abs. 1만 적혀 있습니다.

## 법령 추가하기

법령 이름은 모두 [laws.py](laws.py)에서 가져옵니다. 법령을 추가하는 순서는 다음과 같습니다.

1. `LAWS`(약칭 → gesetze-im-internet.de 주소)와 `CORPUS`에 추가합니다. 다루는 분야가 바뀌면 `TOPIC`과 `OUT_OF_SCOPE`도 고칩니다.
2. 받고, 파싱하고, 인덱스를 다시 만듭니다.

```bash
python gii_parser.py fetch
```

```bash
python gii_parser.py parse
```

```bash
python retrieval.py build --store chroma
```

3. 평가를 다시 돌려 이전 코퍼스와 비교합니다.

AsylG가 이 방식으로 추가한 첫 법령이고, 이어서 EStG, AO, SGB IV, SGB VI를 추가했습니다. 이때 파서를 세 가지 고쳤습니다. 사회법전은 다른 권을 서수로 부르고("§ 28e des Vierten Buches" = SGB IV) 자기 권을 "dieses Buches"라고 부릅니다. "§§ 286 ff."나 "Buchstabe a oder b der Abgabenordnung" 같은 표현에서 법 이름 앞에서 멈추던 문제도 고쳤습니다. 또 법령 약칭에 띄어쓰기가 들어갈 수 있게 했습니다("SGB VI"). 같은 수정으로 기존 AufenthG 상호참조 몇 개도 바로잡혔습니다(예: § 87 Abs. 2가 SGB II·XII 대신 AufenthG §§ 7, 23을 가리키던 것). 2026-10-12에는 AufenthV, FreizügG/EU, StAG, BMG, SGB V, VVG를, 2026-10-13에는 KSVG(예술인사회보험법)를 추가했습니다. 이때 파서가 약칭의 슬래시를 폴더 이름에서 빼도록 했고(`FreizügG/EU`는 `data/raw/FreizügG_EU/`에 저장), 공식 원문의 띄어쓰기 오류(BMG § 3의 "§ 50 Absatz 4den")에도 멈추지 않게 했습니다. StAG는 XML에 조항 제목도 목차도 없어서 본문만 색인됩니다. AsylG 본문은 2024년 EU 망명제도 개혁(2026년 6월 시행) 이후 버전이라, 청크 374개 중 86개가 EU 규정 2024/1347, 2024/1348, 2024/1351을 가리킵니다. 이 규정들은 gesetze-im-internet.de에 없어서 코퍼스에도 없습니다. 답변 프롬프트는 이 경우 세부 내용을 지어내지 말고 EU 규정에 있다고 밝히도록 되어 있습니다.

## 면책 고지

GesetzPolyglot은 독일 법령 이해를 돕기 위한 연구용 시제품이며, 참고용으로만 사용해야 합니다.

- **자문이 아닙니다.** 일반적인 법률 정보를 제공할 뿐, 법률·세무 자문이 아닙니다. 외국인청, 연방이민난민청(BAMF), 망명 절차 상담, 변호사, 세무사를 대신하지 않으며 개인의 사안을 판단하지 않습니다.
- **망명 절차의 기한은 짧습니다.** 망명 절차에서 결정문을 받았다면 바로 상담을 받으세요. 기한이 1–2주인 경우도 있습니다.
- **답변이 틀릴 수 있습니다.** 답변은 언어 모델이 자동으로 생성합니다. 조문을 인용하고 인용 검증을 통과하더라도 불완전하거나 최신이 아니거나 틀릴 수 있습니다. 사용한 법령 스냅샷 날짜는 답변마다 표시됩니다.
- **원문을 확인하세요.** 인용된 원문을 gesetze-im-internet.de에서 반드시 확인하고, 개인 사안은 자격 있는 전문가와 상담하세요.
- **책임을 지지 않습니다.** 법이 허용하는 범위에서, 작성자는 이 답변에 근거한 결정이나 행동, 답변에 대한 과도한 신뢰, 이 소프트웨어의 오용에 대해 책임을 지지 않습니다. 이 소프트웨어는 어떠한 보증도 없이 "있는 그대로" 제공됩니다.

같은 고지가 웹 앱에도 표시되며, 모든 답변 끝에는 질문 언어로 된 짧은 고지가 붙습니다.

## git에 올라가지 않는 것

`data/index/`(임베딩과 Chroma 포함), `results/`, `.env`, `.venv/`는 `.gitignore`에 있습니다. 저장소를 받은 사람은 위의 1–2단계로 데이터와 인덱스를 다시 만들고, `eval_retrieval.py`와 `eval_answers.py`로 평가를 다시 돌리면 됩니다. LLM 실험에 쓴 문항 목록은 [evalset/splits.json](evalset/splits.json)에 있습니다.
